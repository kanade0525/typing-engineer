# Typing Engineer

> 自分でコードを書かなくてもプロダクトが出来上がる時代に、私はコーディングをしたいのです

HTML と CSS を一字ずつ打つタイピング練習。
**打った分だけ、右側のプレビューがその場で組み上がっていきます。**

<https://kanade0525.github.io/typing-engineer/>

---

## 何が見えるのか

| 題材 | プレビューの動き |
| --- | --- |
| HTML | 打った所までを `document.write` で継ぎ足す。ブラウザが実際にページを読み込むときと同じ流し込みなので、閉じタグを打つ前でも途中まで形になる |
| CSS | 土台の HTML は置いたまま `<style>` の中身だけ差し替える。ちらつかず、アニメーションも動いたまま |
| JS | 文法が通った時点で走らせる（打つ手が止まってから）。途中の JS は動かないので一字ごとには流さない |

**JS の課題の `sandbox` について。** `allow-scripts` だけにすると出所が不定のページ扱いになり、
`localStorage` もフォームの送信も使えません。保存を教える章も追加ボタンも成立しないので、
`allow-same-origin` と `allow-forms` を足しています。この二つを併せると中から `sandbox` を
外せるようになるため、ふつうは避ける形です。ここで許しているのは、**走らせるものが必ず
同梱した文字列そのもの**だからです。打ち手が入れた字は元コードと突き合わせていて、
一致しない字は先へ進みません。外から来た文字列が走ることはありません。

**一覧で札に触れると、打ち終えた姿が出ます。** 題と打鍵数だけでは何ができるのか
分からないためです。動くものは動いた状態で覗けます。

**待機画面では右に完成形が出ています。** <kbd>Space</kbd> を押すと消えて、そこから自分で組み上げます。
打っている途中も上帯の「完成形」で見比べられます。

## 写経する

**一覧に出るのは作品名です。** 「台と玉を描く」は手段でしかなく、
それを見て打ちたくなる人はいません。作品名と「打ち終えると何ができるか」を先に出し、
章はその中の段取りとして並べています。

前章のコードが土台として最初から効いていて、打つのは今の章の差分だけ。
一章 300〜700 打で、章の終わりごとにできることが増えます。

### アプリを写経する — メモ帳（CRUD）

| 章 | 打ち終わると |
| --- | --- |
| メモの一覧を描く（Read） | 三件が並ぶ |
| メモを追加する（Create） | フォームから足せる |
| メモを済みにする（Update） | 押すと打ち消し線が付く |
| メモを消す（Delete） | × で消せる |
| 閉じても残るようにする | localStorage に残る |

### ゲームを写経する

ぷよぷよ写経の形です。**章ごとに前章のコードが土台として最初から効いていて**、
打つのは今の章の差分だけ。一章 300〜700 打で、章の終わりごとに動くものが増えます。

| 章 | 打ち終わると |
| --- | --- |
| 台と玉を描く | 板と玉の置かれた台が出る |
| 板を矢印キーで動かす | 「遊ぶ」で操作できる |
| 玉を飛ばす | 壁で跳ね返って動き続ける |
| 板で打ち返す | 当たり判定が効く |
| ブロックを壊して得点 | 崩せるものになる |

クリア画面の**「遊ぶ」**を押すと、焦点がプレビューに移って実際に遊べます。

`<head>` を打っている間はまだ画面に何も出ないので、そのあいだは
プレビュー欄の見出しに `<title>` が出ます。

## 見た目

単色の燐光を選ぶと 2020 年の版の面影が出ます。黒地に `#35E02E`、上帯は緑地に黒文字
（当時の `.navbar` そのまま）、打った字だけが燐光します。四角い端末カーソル、走査線。

**配色は 11 種。** 既定は「カラフル」です。

| 系統 | |
| --- | --- |
| **エディタ配色** | カラフル／Dracula／Monokai／Nord／Gruvbox／Tokyo Night。コードの意味ごとに色を分ける。滲みと走査線は切る（色の違いが読み取りにくくなるため） |
| **単色の燐光** | グリーン／アンバー／シアン／マゼンタ／モノクロ。`--tone` 一つから全部を導く。2020 年の版の面影 |

**グリーンを選んだときだけ**、一覧の背後に字が降ります。
Matrix の意匠なので、緑に紐づけてあります。打鍵画面では止まります。

どの色でも文字が読めることは `npm run check` が実測しています。
**地の色との対比**を測るので、地が黒でないカラフルでも甘くなりません。

**走査線はプレビューには掛けていません。** 右に出るのは本物のページで、
CRT の中の絵ではないからです。

`prefers-reduced-motion` が有効なら、降る字は止まります。

## タイムを競う

ステージを選ぶと待機画面が出ます。**<kbd>Space</kbd> を押すと 3 → 2 → 1 → スタート**、
そこから計り始めます。押すまでは待つので、身構えてから始められます。

二回目からは**自分の最速と競えます。** 上帯に `best 41.2s` と現在の差（`-1.4` / `+2.1`）が出て、
進み具合の帯には最速がいま走っている位置が白い線で出ます。追い抜けば緑、遅れれば赤。

サーバーには何も送りません。競う相手は過去の自分だけです。

## 遊び方

1. **英数入力に切り替える。** 日本語入力のままだと打鍵が届きません（気づけるよう画面に出ます）
2. 課題を選んで、上から順に打つ
3. **行頭のインデントと色の値は自動で埋まります。** 改行は <kbd>Enter</kbd>。
   `#1f2937` なら `#` を、`rgba(15, 23, 42, 0.14)` なら `rgba(` を打った時点で残りが埋まります。
   実務でも手では打たずコピーしてくる所だからです。
   埋まった分を見たままなぞって打っても、ミスにはなりません。
   `translateY(-46px)` や `linear-gradient(135deg, ...)` の中身は色ではないので打ちます
4. 間違えるとカーソルは進みません。正しい字を打つまで止まります

<kbd>Esc</kbd> で一覧に戻ります。

## 言語

**日本語と英語。既定は日本語です。** ヘッダーで切り替えます。

画面の固定文言は `data-i18n` で印を付けて `assets/js/i18n.js` から流し込み、
課題・作品・アチーブメントの文言はそれぞれのデータが `en` を持っています。

**訳の抜けは `npm run check` が拾います。** 片方の言語にしか無い鍵、
`en` を持たない課題、そして**英語に切り替えたときに画面へ残る日本語**を落とします。

## 画面

| URL | 何の画面か |
| --- | --- |
| `#/` | ステージ一覧 |
| `#/mypage` | マイページ |
| `#/play/<id>` | 打鍵画面（例 `#/play/css-first`） |

URL で画面が決まるので、**ブラウザの戻る／進むが効き、ステージへ直接リンクできます。**
画面ごとにタブの題も変わります。

一覧は <kbd>←</kbd> <kbd>→</kbd> <kbd>↑</kbd> <kbd>↓</kbd> で選び、<kbd>Enter</kbd> で始められます。
マウスを使わずに最後まで行けます。

## マイページ

`#/mypage` に、記録をぜんぶ出しています。

- **ランク**（スコアで上がる。ROOKIE → CODER → BUILDER → ENGINEER → ARCHITECT → OPERATOR → THE ONE）と次までの残り
- クリア回数・ステージ制覇数・総打鍵・最速・最高正確さ・連続日数・ノーミス回数・はじめた日
- **ステージ別の記録**（クリア回数／ベストタイム／wpm／正確さ）
- **アチーブメント**（取得日つき）
- **最近の記録**（直近 20 件。日時・タイム・wpm・正確さ・スコア）
- **記録の置き場所**。localStorage の鍵まで書いてあります。JSON で**書き出し・読み込み**ができ、消すこともできます

## 打ち終わったコードを持ち帰る

クリア画面から、打ったコードをそのままコピーできます。
**「ページを保存」**は、ブラウザで開けば動く一枚の HTML にして落とします
（CSS の課題なら土台の HTML と `<style>` をまとめた形）。

## 結果を共有する

クリアしたら「結果を共有」で外に出せます。端末が共有画面を持っていればそちらへ、
無ければ X の投稿画面を開きます。**どちらも最後に自分で押さないと出ていきません。**
送るのはステージ名・タイム・正確さと、そのステージへの URL だけです。

## アチーブメント

クリアするたびに**スコア**が入ります。打鍵数・正確さ・速さの掛け合わせなので、
速いだけでも正確なだけでも伸びません。

```
SCORE = 打鍵数 / 10 × 正確さ × (1 + wpm / 100)
```

**アチーブメントは 16 個。** 全ステージクリア、ノーミス、時速四十／六十／八十、
通算一万打、三日つづける、午前 0 時から 4 時のあいだにクリア、など。
取っていないものも条件は見えているので、次に何を狙うかは分かります。

**記録は手元のブラウザにだけ残ります。** サーバーには送っていません。
どこに何が入っているかはマイページに全部書いてあります（`typing-engineer:best:v1`、
`typing-engineer:stats:v1`）。JSON で書き出せますし、消すこともできます。

順位表を作るとサーバーが要るうえ、ブラウザから送る数字は必ず偽装できます。
自分の積み上げだけなら、ごまかして損をするのも自分だけで済みます。

## 手元で動かす

```sh
npm run dev     # http://localhost:8000/
npm run check   # 下の検査。落ちたら終了コードが 1 になる
```

`npm run dev` は `_headers` を読んで同じヘッダーを付けます。**手元と公開先で
CSP が食い違うと、破ったことに気づくのが公開後になる**ためです。

## 公開先

いま **GitHub Pages と Cloudflare Workers の二本を並走させて**見比べています。

| | |
| --- | --- |
| GitHub Pages | 現行。帯域幅 100 GB/月（ソフト）。**ヘッダーを一切指定できない** |
| Cloudflare Workers | 静的配信は無料・無制限。`_headers` で CSP を置ける |

移す理由は帯域幅ではありません（264 KB のサイトで 100 GB には届きません）。
**ヘッダーを置けることです。** 上の「外部に依存しない」を宣言から
不変条件に変えられるのは、こちらだけです。

`_headers` は GitHub Pages では単に無視されるので、並走中に困りません。
ハッシュルーティング（`#/play/...`）なのでリライトの設定も要りません。

### Pages ではなく Workers

Cloudflare には Pages と Workers の二つがあり、**Workers を選びました。**
Cloudflare 自身が「新規プロジェクトは Workers で始めるべき。Pages は引き続き
サポートするが、今後の投資・最適化・機能開発は Workers に専念する」と
言っているためです。静的アセットの `_headers` はどちらでも同じ構文で使えます。

`wrangler.jsonc` に `main` は書いていません。振る舞いを足すつもりが無いので、
アセットを配るだけで足ります。Worker のコードが無いぶん、動く部分が減ります。

`assets.directory` は `.` です。`index.html` があるのがリポジトリの根で、
**`_headers` もそこに要る**ためです。Workers は `_headers` を
アセットディレクトリの直下でだけ読みます。

配りたくないものは `.assetsignore` で外します（`tools/` `scripts/` `README.md`
など）。`_headers` は書きません。あれは Worker が読んで解釈する設定で、
アセットとしては配信されないからです。

**この二つのファイルは `npm run check` が検査しています。**
とくに `_headers` がアセットディレクトリの直下にあること。ここがずれると
**CSP が黙って効かなくなります。** 落ちも警告も出ず、ヘッダーだけが消えます。
しかも手元の `npm run dev` は根から読むので通ってしまいます。

## 検査（`npm run check`）

| 見ているもの | |
| --- | --- |
| 題材データ | id の重複、必須の項目、分類が GROUPS にあるか、**打つ字が ASCII だけか**、打鍵数が 120〜1200 に収まるか、題が動詞ひとつで終わっていないか |
| 訳 | 課題・作品・アチーブメントが `en` を持つか、辞書の鍵が両言語で揃っているか、画面の印が辞書にあるか、**英語で日本語が残っていないか** |
| 描画できたか | **一覧に札が一枚も出ていなければ落とす。** これが無いと、読み込みで落ちて真っ白でも下の検査は通ってしまう |
| README | **書いてあるとおりに手を動かして壊れないか。** 題材・配色・アチーブメントの数、構成の一覧に `assets/js` の全ファイルが載っているか、そして**「題材を足す」の例が実際に検査を通る形か**（項目の抜け、`GROUPS` に無い分類、`en` の抜け） |
| リンク | **ブラウザ既定の下線が出ていないか**（`.credit` は狙って引いているので除く） |
| ボタン | 既定の見た目が残っていないか（`cursor` と角丸） |
| 色 | **どの配色でも文字が読めるか。** `--pending` `--fg` `--fg-mid` `--fg-dim` と字句の色の、**その配色の地**に対する対比を実測し、4.5:1 を下回ったら落とす（注釈だけは 3:1） |
| 幅 | 横に溢れていないか |
| 公開の設定 | **`_headers` が `assets.directory` の直下にあるか。** ずれると CSP が黙って効かなくなる（手元の `npm run dev` は根から読むので通ってしまう）。`.assetsignore` が `index.html` や `assets/` を外していないか |
| CSP | **二方向から見る。** 壊していないか（5 言語ぶんの完成形を描いて違反ゼロ、JS 課題は canvas に色が乗ったかまで見る）と、効いているか（外へ `fetch` して **CSP が止めたことを違反の発火で確かめる**）。`fetch` の失敗だけを見ると CORS や不通と区別が付かず、CSP を消しても通ってしまう |

**依存パッケージは足していません。** Chrome を起動して DevTools Protocol を直に叩いています。

下線の検査を入れたのは、`text-decoration` の指定が無くて既定の下線が全リンクに出ていたのを
長いあいだ取り逃したからです。既定値はエラーを出さず、動きも壊しません。撮った画像も
「機能が正しく見えるか」で読んでいて気づけませんでした。**この種類は computed style を
実測して不変条件を置くしか捕まえようがありません。**

依存パッケージはありません。`npm install` も要りません。
ES モジュールを使っているので `file://` で直接開いても動かない、それだけの理由で
サーバーを一本置いてあります。

  preview.js        打った所までを描く
  highlight.js      HTML / CSS の色分け（依存なしの字句解析）
  lessons.js        題材と作品
  i18n.js           日本語と英語の文言

  matrix.js         緑のときだけ一覧の背後に降る字
  mypage.js         マイページの組み立て
  trophies.js       スコア・ランク・アチーブメント
  storage.js        自己ベストと記録（localStorage）
  sound.js          打鍵音（音声ファイルは持たず合成する）

`view-compose.js` と `view-routes.js` があるのは、Docker も Rails も
ブラウザでは動かせないからです。動かせない代わりに、**打った内容を読んで
図と表にします。** `resources :posts` と打った瞬間に七行が現れます。

### 題材を足す

`assets/js/lessons.js` に一つ足すだけです。**`code` は必ず ASCII だけで書きます。**
日本語が混ざると IME が要り、打鍵を受け取れなくなります。

**`en` も要ります。** 無いと英語に切り替えたときそこだけ日本語で残るので、
`npm run check` が落とします。

```js
{
  id: 'css-gradient',
  group: 'patterns',  // 'visual' 'patterns' 'apps' 'games' 'config' 'basics'
  lang: 'css',        // 'html' 'css' 'js' 'yaml' 'ruby'
  file: 'hero.css',
  level: 3,           // 1〜4
  title: '背景をぼかす',
  subtitle: 'グラデーション',
  note: '一覧のカードに出る一行。',
  en: { title: 'Blur the background', subtitle: 'Gradients', note: 'One line on the card.' },
  scaffold: '<div class="hero">Hello</div>',  // lang が 'css' 'js' のときは要る
  code: '.hero {\n  background: linear-gradient(...);\n}\n',
}
```

**この例そのものを `npm run check` が検査しています。** 項目が足りない、
分類が `GROUPS` に無い、といったズレは落ちます。README を写して手が止まる、
ということが起きないようにするためです。

## 外部に依存しない

フォントも CDN もアイコン配信も使っていません。ネットワークへ出ていく通信はゼロです。

2020 年の版は Heroku・Font Awesome・期限付きの署名付き S3 URL に寄りかかっていて、
Heroku の無料プランが終わった時点で丸ごと動かなくなりました。同じ壊れ方をしないよう、
外に置いたものは持ち込んでいません。

**これは長いあいだ宣言でした。いまは `_headers` の CSP が強制します。**
`connect-src 'none'` を置いてあるので、うっかり CDN の URL を書いた時点で
ブラウザが止めます。効いていることは `npm run check` が実測しています
（外へ `fetch` して、CSP が止めたことを違反の発火で確かめる）。

`script-src` と `style-src` の `'unsafe-inline'` は外せません。打った字を
`srcdoc` に流して走らせるのがこの入れ物の主題で、中身は一打ごとに変わるので
ハッシュも nonce も置けません。**ここで守れるのは「インラインを止めること」ではなく
「外に出る通信をゼロに保つこと」です。** `connect-src` が本体で、あとは付随です。

## 2020 年の版から変わったところ

- **公開先** Heroku（消滅）→ GitHub Pages。サーバーは要らなくなりました
- **打つ字** `&lt;` `&gt;` という実体参照を打たせ `keyCode` で分岐していたのをやめ、
  `<` `>` をそのまま打ちます
- **プレビュー** 新設。これが今回の主題です
- **単位** 1 行ずつ → ファイル 1 本を通しで
- **見た目** 黒地に緑一色 → エディタ風の配色と、打った所だけ色が点く表示
